# Groovebox — Ideal Harmonization Sequencer Generator and Algorithmic Tool

## Project goal

Groovebox is an **Ideal Harmonization Sequencer Generator and Algorithmic Tool** for constructing, harmonizing, transforming, auditioning, and rendering musical sequences through deterministic mathematics, numerical seeds, rhythmic generation, phase relationships, pitch systems, audio analysis, and algorithmic composition engines.

The central design goal is **canonical unison**: multiple engines can participate in the same composition without destroying one another's state. User edits remain distinct from engine-owned material, while Euclidean rhythm, seeded randomization, Phase-Locker, PKP NullLock, GOAVA, and Meum calculus can cooperate as a coherent generative system.

## GOAVA mathematics

GOAVA is the Java numerical composition algorithm supplied with the project. Groovebox preserves its numerical character rather than treating GOAVA as an ordinary randomizer.

For a numerical seed/value `n` at sequence step `s`, the conceptual core is a cosine accumulation over the supplied values:

`S(s) = Σ cos((n_j + s) / (j + 1))`

The accumulation is normalized by the number of supplied values and passed through the GOAVA arpeggio/frequency mapping used by the Java implementation. Groovebox retains three identities for each generated event:

1. **Seed identity** — the original numerical value.
2. **Raw identity** — the deterministic GOAVA cosine-derived scalar.
3. **Musical identity** — the resulting frequency/pitch ratio.

GOAVA is engine-owned. Turning it off removes GOAVA-owned data without deleting user material or the canonical data generated by other engines.

## GOAVA + canonical unison weighting

GOAVA can participate as a **single weighted playlist contribution** while the canonical engines remain active. The weighting is normalized over the active contributors:

- GOAVA alone → `1/1`
- GOAVA + one canonical engine → `1/2` each
- GOAVA + Randomizer + Phase-Locker → `1/3` each
- GOAVA + `N-1` active canonical contributors → `1/N` each

The normal comma-separated canonical operator/member playlist field is not replaced by GOAVA. GOAVA writes its own weighted entry and metadata, allowing the canonical engines to continue painting their own lists.

## Meum calculus and the visual engine

The Meum scenograph converts live audio analysis and composition state into a mathematical visual field. Its contextual keys include formation `u`, radial scale `rho`, form, line density, spectral centroid, RMS/peak energy, rhythm stability, structural density, seed values, and playhead position.

GOAVA values become numerical geometry keys:

`GOAVA seed → GOAVA raw value → visual key → 1D / 2D / 3D geometry`

Meum analysis then determines how those shapes are expressed through scale, rotation, topology, density, color, depth, and timing.

### Visual behavior

The scenograph is intentionally not a permanent collection of visible objects.

- **Silence / low energy:** contextual fields, constellations, sparse lattices, and slow mathematical structures can remain active.
- **Loud transients:** bursts, spectral comets, rapid filaments, and strong surfaces become prominent.
- **Stable rhythm:** rhythm mandalas, pulse grids, coherent orbitals, and formed faces become more prominent.
- **Chaos:** minor/background structures attenuate while high-information structures take precedence.
- **GOAVA activity:** numerical 1D filaments, filled 2D forms, and visibly formed 3D projected surfaces respond directly to GOAVA values and Meum audio keys.

Modules can fade completely out, return, and cross-fade according to contextual relevance. The visual field is designed to behave as an additional compositional layer rather than a permanently visible overlay.

## PKP NullLock BOOST

PKP NullLock BOOST is a playover modulator. Its pitch control can transpose the boost independently, while **Steps to Play** controls its duration from one step through one complete sequence length. The playover remains non-destructive to the programmed sequence.

## Playlist integrity

The canonical comma-separated operator/member fields remain authoritative for their respective engines. GOAVA uses its dedicated fields and weighted unison metadata, so enabling GOAVA before the other canonical engines cannot blank or overwrite their lists.

## Visual philosophy

Groovebox seeks an expressive middle point between mathematical order and entropy: coherent enough to reveal rhythm, harmony, and structure, but variable enough that geometry can form, dissolve, implode, reappear, and change dimensional character as the music changes.


## V6 sequence composition and canonical unison

Every instrument now owns a numbered sequence bank. `Add sequence`, `Remove sequence`,
and `Select sequence` operate on the active instrument only, while each sequence stores
its own pattern length. Playlist rows record deterministic sequence references and phase
offsets, allowing the same sequence to be reused recursively without converting the
composition into a best-fit fit operation.

The canonical set is GOAVA, Randomizer, Phase-Lock, Euclidean, and Seeded Randomizer.
Each non-GOAVA canonical stores an independent playlist contribution; the reconciler
unions active contributions rather than inferring ownership from the last-written row.
GOAVA remains isolated in its dedicated playlist field and is a singular sine oscillator
whose frequency moves above or below the global base frequency.

When canonical engines are active, userdata is allocated 50% of the canonical signal
and the active canonical engines divide the remaining 50% equally. The
`Canonical: skip overwrite user composition` toggle remains the ownership boundary:
seed values are global composition inputs, never userdata. Sequence banks and user
snapshots are serialized with the project so engine toggles and ensemble resizes do
not destroy human-authored material.

The Meum scenograph uses a separate seeded stochastic stream per rendered frame.
This makes visuals evolve and decorrelate across rational/irrational seed strings while
leaving audio/unison generation deterministic. Projected elements are individually
clamped to the fitted frame so stochastic evolution cannot escape the visible screen.
