# Universal Field Rollout — 2026-09-05

The canonical architecture is now:

`canonical input -> Universal Field -> N-part factorization -> independent audio / visual / game / export projections`

N never enters Universal Field identity.  It only changes how the same state is distributed among part objects.  `partition_field()` gives each object rational weight `1/N`, and `reconstruct_parts()` must recover the upstream coordinates within floating-point precision.

## Scale policy
Structural anchors: 0, 1/2, 1.
Traversal/index ratios: M−1, 1/M, 2−M, (M−1)/M, √2−1, φ−1, e−2, π−3.
Irrational values are not used as arbitrary share weights.

## Visual projections
Canonical Geometry; Meum Field; Isosceles/ISN Scope; OT Transform Graph; Phase Torus; Lissajous/Harmonic Orbit; Spectrogram; Partial Constellation; Canonical Delta; Sequence Geometry; Playlist Timeline Terrain; Number-Theory Scope; Fractal/L-System; Complex Plane/Riemann; Wave Surface; Vector/Flow Field; Seed Fingerprint; Network Radio Constellation; Game World Map; A/V/G Correspondence.

Each projection is a deterministic selected/complement split of the same Universal Field. Selected + complement reconstruct the original field coordinates.

## Game contract
The generated game receives `universal_field_state` and `game_projection_state`. Gameplay uses the projection for event/hazard weighting, NPC interaction timing, world/remote motion scaling, lighting/activity metadata and map/A/V/G state. Instrument count is excluded from composition identity and from Universal Field creation.

## Regression requirement
For the same seed/composition and N in 1,2,4,8,16,32,64 (and higher where useful), Universal Field ID, game projection, and reconstructed field must remain identical within floating-point precision. GUI runtime still requires a PyQt6-equipped host for direct widget smoke testing.
