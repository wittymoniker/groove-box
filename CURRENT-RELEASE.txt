R31.7 — AUTOMATION MORPH SPAN 0–100%
- Automation points previously coupled their morph result 50% with the composition step and 50% with the
  instrument's panel patch, so Morph 100% only reached halfway to state B. New project setting MORPH SPAN %
  (50–100, automation bar): 100% = full A→B reach (new default). Saved per project, part of the render key, used
  by exports. Projects saved before R31.7 load at 50% (unchanged sound); raise it to get the full span.

R31.6 — UNIVERSAL SEEDS, SHARED CANONICAL DECISIONS, NO HARD OUTPUT LIMITS
- spectral_canonical.py: seed ↔ audio canonical. Literal seeds "MGLS1:" hold the exact STFT (perfect-reconstruction
  sqrt-Hann, 50% overlap): Analyse any audio file → seed → identical audio (max error ~6e-8, float32 rounding).
  Generative seeds of ANY length (SHAKE-256 stream; no 64-bit collapse): every byte decides spectra, partials,
  phase, noise and dynamics. Mono, stereo or N channels.
- video_canonical.py: seed ↔ video canonical. Literal seeds "MGLV1:" hold every frame's 2-D DCT: exact uint8 frames
  back. Generative seeds of any length decide palette, low-frequency structure, motion and texture.
- Export ▸ "🧬 Spectral & Pixel Seeds…" (also ⚡ Actions): Analyse a file → seed, Load/Save .gbseed, Generate,
  Verify round trip, export 32-bit float WAV / FFV1 MKV / MP4, "Use as carrier".
- canonical_decision.py: one shared decision layer. Canonical active → time-invariant canonical value × activation
  level (module default disregarded); otherwise default × Morph Bridge mix, with an optional time-variant fallback.
  The multidim stochastic responses now go through it (same values as R31.5). app.canonical_decide(...) and
  app.canonical_decision_context() expose it to every module, thread and worker process.
- Audio export: "32-bit float" bit depth (IEEE float WAV, no quantization) and "Bypass master hardclip" (master volume
  only; with float the overshoots are kept). Render rates up to 192 kHz were already available. Multichannel masters
  are written as-is; true stereo/N-channel generation is available through the spectral canonical.
- Structural caps raised: playlist rows, sequence/pattern lengths, automation points and preview rows 1024 → 65 536;
  synth count / sequence ids 128 → 512 (GROOVEBOX_MAX_STEPS / GROOVEBOX_MAX_VOICES override). Memory is the limit.

R31.5 — MULTIDIM STOCHASTIC RESPONSES
- Canonical path (any canonical active, level > 0): stochastic probability = the canonical decision module's
  seed/slot value × the activation level; each block's decision is a pure hash of (seed, slot, ABSOLUTE timeline
  block), so responses are time-invariant (identical however the render is chunked). The default is disregarded.
- Fallback (no canonical probability / activation): internal default probability 0.19758 × the new Morph Bridge
  slider "Multidim Stochastic Default" (0–1, label shows the resulting p); the probability drifts along the
  timeline (time-variant), still deterministic so play and export match. Saved with the project; in the render key.
- The existing smooth stochastic / fractal / lock field now indexes absolute timeline blocks instead of restarting
  at every row (changes exported sound slightly for projects using Randomizer / Seeded — intentionally).
- Verified: chunked == whole decisions; p scales with level (1.0 → 0.60, 0.5 → 0.30, 0.1 → 0.06); fallback p =
  0.19758 × mix; observed fire rate matches p (0.363 at p = 0.36); voice renders respond as specified.

FASTER EXPORTS + 4K (R31 performance pass)
- PARALLEL VIDEO PARTS: a video export with 2+ parts is split across the warm workers: each worker renders a set
  of .partNN segments (video only, always resuming so siblings never delete each other's parts), then a final job
  writes the audio and stitches. Same semantics as the existing resume (a part starts with a fresh engine), so
  wall time ≈ total / workers. "Start fresh" clears old parts once, before splitting. Export Jobs shows each part set.
- NATIVE LINE RASTERISER: VideoSynthEngine._line runs in the Rust accelerator (C++ fallback), an exact twin of the
  NumPy path; frames are bit-identical (verified on 6 frames). ~24% less time per frame on its own.
  Build flags gain -ffp-contract=off so native float32 blends can never round differently.
- 4K PROCESS RIG: FULL CPU ▸ "4K stream" now renders live video in separate rig_worker processes (one interpreter
  / GIL each, cores − 2), frame-parallel with the newest frame winning, render size adaptive, output 3840×2160.
  rig_worker is a registered helper module, so it also runs from the frozen EXE. Workers keep stdout for frames
  only (app prints go to stderr). Measured: the engine is geometry-bound (~1.2 s/frame at any size), so this
  4-core machine delivers ~2 fps from 3 processes; real-time 4K needs the engine's per-frame Python geometry
  vectorised (next step).
- Audio exports: already faster than real time on a quiet machine after the resonator fix; a single track is
  not split across processes because the per-voice phase carry runs row to row (see notes).
