Root cause confirmed against the Debian 13 6.12 kernel module layout available in the build environment:
  ext4 hard dependencies: jbd2, crc16, mbcache
  crc32c is an algorithm-provider dependency and is not in ext4's hard module dependency list.
  Debian provides crc32c_generic.ko and crc32c-intel.ko; both advertise the crc32c/crypto-crc32c aliases.
  Therefore an ext4-only dependency closure can pass /proc/filesystems yet still fail at a real metadata-checksummed mount.

  PASS: installer loads CRC32C providers before ext4 and verifies /proc/crypto before any target erase/write.
