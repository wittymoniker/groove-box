R32.9.2 (2026-11-10) — keyboard loop + held-note sustain repaired; written and compile-checked, not run
  * Why the Return loop stopped working: piano keys moved to an app-wide filter, but Return and key RELEASES
    still went to whichever control had focus (a button / spin box ate Return; Main never saw releases).
    Return/Enter and releases now go through the same filter as the notes (active Groovebox window, no popup,
    not typing in a text field).
  * Loop logic rewritten: Return ① record · ② close the loop (length = time recorded) and play · ③ clear.
    (Before, Return after playing re-armed the loop and erased the notes.) Notes keep their pitch (they all
    played as degree 0 before) and fire exactly once per cycle (the ±60 ms window double- or never-fired).
  * Envelope time in the loop: each note keeps how long it was held and replays with that length.
  * Control lanes in the loop: moves of any automatable parameter (FX, EQ, synth engine, Mod Osc, mixers,
    ball / cellular / wavetable params, expression matrix, game macros …) are recorded at their loop position
    and replayed every cycle; moves made while it plays are ADDED (overdub); a control you are moving is not
    overridden for 0.5 s.
  * Held-note sustain now works on the normal instrument path too (it was only on custom key assignments), and
    the release finds its voice: the mixer stored a view of the buffer, so the identity match always failed and
    held notes rang the full 16 s. The submit now reports the exact object it stores; velocity scaling happens
    before the hold is bound.
  * Live autosave: at most once every 2 minutes and only after a real edit (no restart storm from continuous
    changes).
