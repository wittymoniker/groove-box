Round 2 (2026-11-02, from Latitude/Acer reports)
- audio_os_backend.resolve_output_device_index: on sOS, first resolve the PortAudio row of the SAME physical ALSA PCM that video (mpv) is pinned to (boot state / UCM, cached 15 s); name-scoring remains the fallback. Targets Latitude: video audible, audio player/main window silent.
- audio_check: added tests 1b (file-player stream settings) and 1c (key/trigger stream settings) so the report shows which stream profile a machine cannot make audible.
- audio_check (round 3): added 1d (the running main window's own note engine) and the report now names the resolved PortAudio device and the proven speaker PCM.
- Audio check answers window is now non-modal + always-on-top (the modal exec could hide behind the main window and look like a freeze); the report file is written before it appears.
- Key notes: no fade, no limiter, no soft saturation, no audition peak scaling (all removed at user request; project policy is no limiter/soft-clip)
- All devices, all the time (round 3): every PortAudio output (main window, key notes, Trigger, audio-file player, Audio check) now resolves to the pipewire/pulse device and the "groovebox_all_outputs" combine sink (speaker + HDMI/DP + 3.5 mm + USB/BT) - the same route Performance video uses. The route is built in a background thread at startup (warm_all_outputs_route), the physical speaker's UCM path is prepared like the video path does. Without a sound server it falls back to the proven physical speaker. GROOVEBOX_OUTPUT_SINGLE=1 disables it.
- Round 4: Latitude report - "System default" works for the main window; video needs groovebox_all_outputs or the main ALSA out. The PortAudio "default" device (what a System-default choice resolves to by partial name match) is now preferred before any direct hw PCM and before pipewire/pulse rows, both when the all-outputs route exists (it becomes the default sink) and with no explicit choice. Video routing is unchanged (all-outputs / physical ALSA).
- Round 5: Latitude WAV player was silent while the video player was audible. Audio files in Performance now skip the inline paths (direct-ALSA PCM pipeline and host PortAudio file player) and take the video player route (external player + selected output routing). GROOVEBOX_AUDIO_VIA_PLAYER=0 restores the inline paths. "Play together" (multi-file mix) still uses the host file player.
- Round 6 (all devices, stronger): (1) FOUND THE ERROR SOURCE: open_output_stream raised "selected device is not a usable playback endpoint" whenever the preferred name was "groovebox_all_outputs" (which Performance stores as the preferred name), so every open failed once Performance had run. Bad preferred names now mean "all outputs / no specific device". (2) The output open no longer sits behind the 1.5 s failure cooldown and no longer gives up on the first refusal: it tries the resolved device, system default, pipewire/pulse, every hw output, then re-enumerates and tries again; only when all refuse does it raise. (3) New multi_output.FanOutStream: with no combined sink, one callback plays on every physical output that accepts the same rate/channels (primary drives the callback, secondaries replay it from bounded rings; refusing/failed devices are skipped). Selection is ignored; GROOVEBOX_OUTPUT_SINGLE=1 restores single-device behaviour.
